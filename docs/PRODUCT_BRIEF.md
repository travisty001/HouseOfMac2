HOUSE OF MAC 2.0 — product brief, authoritative interface contract

Audience: a professional 3D field/specimen researcher requiring rigor and clarity. Rebuild from scratch. No previous iteration components or styling. Browser app on local Omarchy, phone as responsive secondary. Preserve original uploaded files, never destructive geometry edits. Scan type detection by content, not just extension, when feasible.

ANTI-SLOP: restrained dark graphite palette, warm off-white type, singular desaturated amber accent, dense-but-breathable layout; no gradient glows, glassmorphism, gratuitous pills or cards, emoji, bogus charts/metrics, marketing language, fake interactions. Use actual responsive CSS; no primary-page vertical scroll. Precision matter: crisp dividers, subtle numeric readouts, context-dependent tools, strong hierarchy. Professional provenance/diagnostic caveats. Typical laptop 1366x768 and phone 390x844. Readable buttons, single unified header, bottom status, compact contextual tool rail. Keyboard shortcuts and discoverability. One primary viewport, optional comparison split—not dashboard grid.

Modes: MESH (GLB/GLTF): texture/neutral/wireframe, lighting including raking-light, clipping-plane with slider, orbit camera, orthographic toggle, calibrated measurement (only if scale supplied), screenshot PNG; SPLAT (native 3DGS PLY/SPLAT/KSPLAT): orbit camera, point-cloud mode, splat size, adjustable alpha threshold if library permits, turntable, screenshot. POINTS (non-3DGS PLY): points renderer, point size, orbit, screenshot. Do not imply PLY always Gaussian—detect header properties such as f_dc_0 / scale_0 / rot_0 / opacity. Detect support before showing mode options. Never present fake pro features, claim photometric relighting of splats, or claim physical measurements from unscaled captures.

Comparison: at most 2 views side-by-side or stacked phone, optional sync camera if supported; no misleading sync toggle. Tabs/segmented mode selection File/Analyze/Compare/Capture should change context without scrolling.

KIRI: User subscribes to KIRI Engine and has installed its Blender addon. KIRI official docs show REST API https://api.kiriengine.app/api/ with API keys, but subscription may not provide developer API key. No direct account access unless configured. Provide polished KIRI workflow launch/help: import exported Gaussian PLY, open official web KIRI reference, identify source KIRI, manage import and original file provenance. Never invent direct login, upload, remote KIRI tasks. If API integration feasible without credentials, wire server-side auth adapter only; otherwise make explicit not connected.

Engine contract: src/engine/Viewer.jsx default export Viewer accepting {asset, settings, onReady, onError, onCameraChange, cameraCommand}. asset {url,name,kind:'mesh'|'splat'|'points'}, settings {appearance:'original'|'clay'|'wireframe', raking:boolean, lightAngle:number, clipEnabled:boolean, clipOffset:number, pointSize:number, splatScale:number, pointCloud:boolean, spin:boolean, speed:number, orthographic:boolean}. Camera command {id,action:'reset'|'front'|'back'|'left'|'right'|'top'|'bottom'|'step-left'|'step-right'}. onReady metadata {type,vertices,faces?}. onError error string. Viewer occupies 100% sized parent. Renderer screenshot: callback through global ref? Instead make Viewer accept captureRef (React ref whose .current function triggers PNG). Other props optional. No multiple independent Three scenes stacked visually. Ensure cleanup correct.

Storage: File via URL.createObjectURL; revoke only after removing asset. sample GLB and 3DGS.ply included in public and accessible. No cloud upload without explicit user action. Avoid holding API secrets client-side.
